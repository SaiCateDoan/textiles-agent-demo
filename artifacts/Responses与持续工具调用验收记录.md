# Responses API 与持续工具调用验收

日期：2026-11-02。

## 实现范围

- 聊天、入库视觉分析及连接检查统一使用 DeepSeek Responses API，不再调用 Chat Completions。
- 支持模型先公开回复，再调用工具；工具完成后可以再次回复并继续调用工具，最终答复才结束本轮。
- 文字增量、工具记录、来源、图表及控件按顺序显示并保存；停止、断连、超时和后续错误保留已经收到的内容。
- DeepSeek 无服务端会话接续，后端完整回传本轮输入、输出及配对工具结果，不使用 `previous_response_id`。

自动测试中聊天与视觉模型使用替身；LanceDB、OCR 等原有真实本地检查仍然保留。前端组件使用内存编译和静态渲染测试，不访问浏览器页面。

## 真实 DeepSeek 验证

先通过真实接口确认 Responses 能在同一响应中返回 `message` 与 `function_call`，并确认流式事件可由当前 SDK 解析。

执行 `uv run --frozen python scripts/acceptance_responses.py`：使用独立 `.cache/responses-acceptance-*` 数据目录和已有 BGE 权重，仅读取标记清楚的模拟定型 CSV 和蓝灰织纹示意 PNG，不覆盖样本或写现有知识库。真实调用 DeepSeek 图片分析及流式 Agent，LanceDB/BGE 均实际运行。

10 项检查全部通过，总耗时 12.58 秒，实际顺序：

1. 模型向用户说明将核对资料。
2. 调用 `list_documents`、`search_knowledge`。
3. 模型再次给出阶段性公开回复。
4. 继续调用 `read_document`、`create_chart`、`create_scenario`。
5. 图表和滑块在对应工具完成时作为产物发出。
6. 模型给出最终答复。

检索结果确实携带原图，聊天模型确实接收到检索图像；完整文字/工具/产物时间线可从数据库恢复，公开结果不包含图片编码或推理过程。机器报告保存在本机 `artifacts/acceptance-responses.json`，按规则不提交。

本轮没有通过 Edge 做视觉验收，也没有把 SDK 验收称为 HTTP 或浏览器验收；浏览器站点权限仍按之前的限制处理。现有前后端服务已加载新代码，端口保持为 8000 / 5173，已有 DOCX 样本改动未覆盖。

协议、状态图、SSE 字段和停止语义详见 [design.md 第 4、8 节](../docs/design.md)。
