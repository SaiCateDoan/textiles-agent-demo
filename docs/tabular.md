# 文档表格与数据集

知识库有两条数据通路：文档表格参与上下文检索；CSV、TSV、XLSX、XLS 的完整记录保存在版本化 Parquet 中，通过 DuckDB 查询。原文件始终保留。现有文档不会被静默重写，点击「重新解析」后才采用新通路；历史回答保留原证据快照。

## 文档内嵌表格

`document_table` 保存 Markdown 表示、完整表头和行、原始行号及关联前后文。DOCX、Markdown、HTML 按原文顺序保留正文与表格；HTML 展开 rowspan/colspan，并保存跨度信息。DOCX 使用声明的重复表头，并根据首部合并单元格恢复常见多级表头和整行表名；不规则布局仍需核对。普通数字 PDF 按表格位置组合正文，排除表格区域内重复的文本行。扫描表格仍走 OCR，不自动承诺精确结构识别。

5000字符以内的表格作为整体分块；较大表格按完整行组拆分，每组重复表头、位置和邻文。较长表格分块建立多个短向量，全部指向同一个完整来源，查询去重后回填整块。字符窗口不是 tokenizer 上限的保证，复杂宽表仍需样本验收。不要把分页读取的一部分当作整表。

界面以 Markdown 表格显示。校对可以修改单元格值，但必须保留表头、列数和行数；结构变化应修改原件后重新导入。旧 `table` 行分块仍可读取和编辑。

## CSV / Excel 入库

- CSV/TSV 以首个非空记录作为表头，保留物理记录行号、全部字段与空值，不按数据行生成向量。
- XLSX 以全空行/列带识别独立数据区域，识别完整宽度的合并标题、从首行延伸的合并表头。并排表格有不同的数据集标识。区域首行含数值/日期且没有明确合并表头时拒绝入库，避免把空行之后的明细当成表头丢弃；这种情况请移除明细内部空行或补齐明确列名。没有空白分隔、布局混杂、转置表、未标注的多行表头仍需整理原文件。
- 数字推断检查整列。批次/编号/代码和前导零文本保持字符串，Excel纯零占位格式也保留补零后的编号；空值是 NULL。Excel 日期保存 ISO 文本，可在 SQL 中 CAST。混合数值与字符串的列保留为字符串，不自动丢弃异常项。
- Excel 百分比保留底层数值和格式说明：`0.03` 显示为 `3%`，不能与值为 `3` 的 `pct` 字段混用。CSV 中的 `3%` 保持文本，可显式转换后计算。
- 第一非空单元格明确为「合计/小计/总计/total/subtotal」的记录排除出明细，排除的行号写入目录和查询来源；这是可检查的规则，不是通用报表理解。
- 每个数据集的目录包括 ID、字段/类型、记录数、少量示例、来源 Sheet/范围、公式状态。目录及图片块可检索，但不能据此推断全表统计。
- 工作簿公式保留表达式（目录最多200个并标记截断）、公式数和缺失缓存数，不运行宏或公式。缓存新鲜度始终视为未验证；缺失缓存保持 NULL，不当作零。需要可信公式结果时请先在兼容的电子表格程序中重算保存。
- 原生 XLSX 图表通过 OOXML 提取标题、系列引用、数值缓存样本和缓存数量；不自动读取外部引用，不保证渲染原始外观。截图仍走原有可选多模态路径，并保留锚定行列。
- XLS 保留单元格值，复杂合并、公式和图表需先转换成 XLSX。

知识库面板可以浏览数据集并按50行分页预览。目录和原生图表说明不允许单独改文本，避免目录与数据不一致；修改原文件后重新导入。

## Agent 查询与图表

`list_datasets(document_id?, offset?)` 每页返回50个可用数据集。`query_datasets(dataset_ids, sql, description)` 查询1至4个数据集，单表别名为 `data`，多表依次为 `data1`、`data2` 等。`_source_row` 是来源记录行号；列名使用双引号。支持过滤、聚合、JOIN、排序、子查询和允许的数学/字符串/窗口函数，不支持CTE。

例如整体不良率：

```sql
SELECT "机台",
       SUM("不良数量") * 100.0 / NULLIF(SUM("检验数量"), 0) AS "不良率_pct"
FROM data
WHERE CAST("日期" AS DATE) >= DATE '2026-10-01'
  AND CAST("日期" AS DATE) < DATE '2026-11-01'
GROUP BY "机台"
ORDER BY "机台"
```

`description` 必须说明范围、单位和聚合口径。系统提示要求区分算术平均与加权比率，JOIN前核实键和粒度；当前没有自动认证的业务指标库，SQL执行正确不代表业务含义已经人工确认。

每次结果包含 query_id、实际 SQL、结果列/行、截断标记和全部来源数据集的版本、工作表、范围、行数及公式状态。query_id 可作为 `[C:ID]` 引用。行数上限只在SQL结果外层应用，不会先取500条原始记录再聚合。来源抽屉保存计算时快照。

`create_data_chart(query_id, x, y, chart_type?, title?)` 只能使用本轮已执行查询的结果。支持柱状、折线、散点和单系列饼图，后端直接取结果数值，拒绝被截断的结果和已过期数据集。复杂图表可扩展这一受控路径；不允许用目录示例调用原来的自由制图工具。

`create_chart` 继续支持文章、文档表格和视觉转写中的数据，以模型整理的形式保存。它和查询结果图有不同的来源标记。工况控件直接读取数据资产，当前要求单数据区域且不超过5000条观测，保留原始行号与快照。

## 查询边界与版本一致性

- SQLGlot 解析并检查单条SELECT、语法节点、函数和数据集别名；DuckDB连接禁用外部访问和自动扩展加载。仅注册服务端验证过的本地 Parquet 数据，不接受用户文件路径。
- 单进程最多2个分析查询；DuckDB计算超时10秒、内存预算512MB。载入前根据Parquet元数据限制所选数据解压后总量256MB；Arrow本身的内存不受DuckDB预算控制，因此这个实现不是无限规模流式分析服务。
- 每次最多500行结果、15万字符结果数据。应先过滤、聚合，再交给模型。超出限制明确报错，不返回伪装完整的样本。
- 文件上传仍限制30MB，Office解压后200MB。CSV每文件、Excel每工作表最多约50万行（另容纳100行表头/说明）或500万个单元格。PDF仍限200页。
- Parquet先写临时文件再原子替换；目录、分块、FTS与active_revision同一事务发布。发布失败继续使用旧版。查询后再次检查版本；旧结果可在历史中阅读，但不能据它生成当前图表。
- 删除文档时删除数据集元数据、独立查询记录，并回收全部Parquet版本；历史聊天内的证据快照按原有规则保留。当前重新解析后的旧Parquet版本保留至文档删除，未设置自动按版本回收策略。

## 验证

`uv run --frozen pytest -q` 包含25001行CSV的完整聚合、精确批次查询、NULL、加权口径、合计去重、跨表JOIN、文档范围、危险SQL拒绝、结果截断、版本切换失败恢复、原生图表、公式缓存、百分比、多级表头、并排区域、多模态图片和前端数据预览API等回归。Agent流程测试使用模拟模型响应，DuckDB、Parquet、SQLite、LanceDB读写均使用实际实现。

设计参考：[Docling文档模型](https://docling-project.github.io/docling/concepts/docling_document/)、[Unstructured元素分块](https://docs.unstructured.io/open-source/core-functionality/chunking)、[LangGraph SQL Agent](https://docs.langchain.com/oss/python/langgraph/sql-agent)、[DuckDB数据读取](https://duckdb.org/docs/2.0/data/overview)。本项目继续使用现有轻量解析器，没有额外引入Docling模型或替换整个Agent框架。
