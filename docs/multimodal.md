# 可选多模态入库

上传选择文件后，在确认框中勾选「启用多模态入库」。每批文件的开关默认关闭，所有重新处理/重启恢复任务沿用该文档上传时的选择；已有普通文档要改成多模态，请重新上传并勾选。

开启后，原文图片和邻近文字会发送给DeepSeek，产生视觉调用费用；默认模型沿用`DEEPSEEK_MODEL`，可用`DEEPSEEK_VISION_MODEL`单独配置，模型必须支持图像输入。默认`deepseek-flash`通过[Responses 图像输入](https://api-docs.deepseek.com/guides/responses_api/)接入，使用`input_image`和`text.format`的JSON模式。没有可用图片时直接运行原来的解析器，不创建视觉请求，也不要求配置视觉模型密钥。

## 行为

1. 从原文流提取图片出现位置。PDF使用显示坐标，DOCX使用段落/运行顺序和表格单元格，PPTX使用幻灯片形状位置，XLSX图片生成保留锚定行列的独立视觉块，数据区域另存Parquet；原生图表按OOXML提取引用，见[表格与数据集](tabular.md)；HTML和Markdown支持内嵌data图片。不是将文章的所有图片统一挂到每个分块上。
2. DeepSeek返回严格结构化判断：可以文字化，或需要保留原图。文字化结果标注为模型转写；保留的图像有视觉描述、来源位置、原图和显示预览。布料/实物照片、低置信度结果保守保留。模型自己报告的confidence不代表经校准的准确率。
3. 保留图片用`[[IMG:16位ID]]`放回原位置。本项目分块器把整个标记视作一个逻辑单元，并禁止重叠窗口将同一位置的图片复制到无关分块；它不是修改DeepSeek或BGE的实际tokenizer。一个分块可拥有多个图片ID。
4. 无可读文字的独立图片生成独立视觉描述段，并附原图。单图视觉描述作为完整语义块保留，不将描述和图片拆到不同段。原图归属信息不依赖OCR是否识别出文字。
5. 嵌入和BM25索引使用原文、视觉描述及可读图片文字，不把不透明图片ID当成语义。向量仍是本地BGE文本向量，不是CLIP等原生图像向量。
6. 检索和原文读取结果带该分块的`images`。Agent返回来源快照时也保存这些图片，前端在分块原位置、来源抽屉和回答引用处展示原图。聊天模型每次提问（一次Agent运行）最多额外接收6张不同的检索原图；所有关联图片仍在来源数据中可查看。

## API

上传仍使用`POST /api/documents`的multipart表单：

```text
file: 文档文件
multimodal: true 或 false（省略为false）
```

文档新增`multimodal`、`image_count`、`retained_images`。`image_count`是本次实际分析图像数，`retained_images`是须随段落保留的数目。状态新增`analyzing`，前端显示DeepSeek视觉分析进度。

分块及检索结果新增：

```json
{
  "text": "原文前半段 [[IMG:0123456789abcdef]] 原文后半段",
  "image_ids": ["0123456789abcdef"],
  "images": [{
    "id": "0123456789abcdef",
    "url": "/api/images/0123456789abcdef",
    "preview_url": "/api/images/0123456789abcdef?preview=true",
    "description": "中文视觉描述（模型生成）",
    "locator": "原文位置",
    "decision": "retain"
  }]
}
```

示例ID仅为结构说明。图片API只接受服务端生成的ID，不接受任意本地路径或外部URL。视觉模型和聊天模型均只接收后端读取并编码的图片；不会通过模型给出的链接抓取文件。

编辑带图文本时必须完整保留原有图片位置标记，可以在本段内调整位置，不能拆碎/删除标记或引入其他图片ID。后端校验失败会返回422，保持原索引不变。

## 版本与存储

- SQLite启动时执行增量迁移，旧文档保持`multimodal=false`；原LanceDB的512维表不需要更换。
- 图片以服务端ID保存在`data/assets/<文档ID>/`。栅格原图保留解码后的原始像素，PNG封装可能与上传文件的字节/EXIF元信息不同；PDF预览另存显示方向正确的区域渲染，不用预览覆盖原始栅格像素。矢量图区域保存原PDF的栅格化区域及源坐标。
- 可以文字化的图片也保留资产用于追溯，但不作为该分块的附图返回；原上传文件始终保留。
- 图片分析全部完成后才发布分块与索引；成功图片结果立即保存，瞬时故障按次数和退避策略自动重试，永久错误或重试耗尽才显示处理失败。不会静默用空OCR结果代替。重新处理沿用多模态设置，未过期检查点可复用已成功结果。
- 重新解析期间及失败后，已发布版本继续可检索；新版本通过校验后切换。任务租约、视觉预算、缓存和保留期见[关键设计说明第7节](design.md#7-大积压与并发入库的实现)。
- 重新解析产生新图片ID，保留旧资产以供历史来源快照查看。删除文档会移除当前和历史版本的原图资产；历史对话文字快照还在，但图片会显示已移除。

## 支持与边界

支持PDF栅格图片、可检测的矢量图区域、DOCX正文/表格/普通页眉页脚内嵌图片、PPTX图片形状、XLSX锚定图片、HTML/Markdown内嵌base64图片和原有支持的独立图片格式。复杂组合形状、跨栏布局或图表裁剪仍需通过「核对原文页」检查。

HTML/Markdown外链和相对路径图片不会自动下载或读取任意邻近文件，缺失原图会提示。请将图片内嵌或改成包含图片的PDF/DOCX。旧XLS仍使用原表格解析器，不保证提取其内嵌图片；需多模态时转换为XLSX。Office中检测到无法定位的图像资产会报告错误，不伪装成无图文档。

默认每个文档最多60张图、同时2个视觉请求，数量上限可通过`MAX_MULTIMODAL_IMAGES`配置；单图最多4000万像素，整份文档标准化图片最多100MB。数量超限在模型调用之前失败，以避免部分调用收费后才发现超限。现有30MB上传和200页/帧上限仍适用。

图像文字、数据点、织物外观都可能被模型误读。简单图表文字化不自动转成可信的数值表，也不直接用于精确聚合；质检数值应导入结构化原表或人工核对。照片不能证明成分、克重、触感或牢度。
